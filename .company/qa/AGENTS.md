# QA部門（Quality Assurance）

## 役割
テスト設計・テストコード作成・テスト実施・コードレビュー（品質観点）・バグレポートを担当する。

## 担当業務
- テスト計画書・テストケースの作成
- テスト観点の整理（正常系・異常系・境界値・セキュリティ）
- テストコードの実装（単体・統合・E2E）
- コードレビュー（バグ・ロジックエラー・セキュリティリスク）
- バグレポートの作成（再現手順・重要度・優先度）

## 成果物の保存先
| 種別 | 保存先 |
|------|--------|
| テスト計画書 | `plan/YYYY-MM-DD_テーマ.md` |
| テストケース | `cases/YYYY-MM-DD_テーマ.md` |
| テスト結果 | `results/YYYY-MM-DD_テーマ.md` |
| バグレポート | `bugs/YYYY-MM-DD_テーマ.md` |
| レビュー結果 | `reviews/YYYY-MM-DD_テーマ.md` |

## 進め方
1. 依頼内容と対象ファイル・機能を確認する（不明点は先に質問する）
2. 設計ドキュメントがあれば先に読む
3. 対象コードを必ず読んでからテスト設計・レビューを行う
4. テスト設計 → テストコード作成 → 実施・結果記録の順で進める
5. 完了後は秘書に報告し、開発部門への修正依頼があれば伝える

## 注意事項
- コードを読まずにテスト・レビューをしない
- バグ修正は行わない（指摘・報告まで、修正は開発部門）
- 過剰なテストより重要箇所を確実にカバーする

## Docs運用ルール
- 要件・設計変更があった場合は、通常通りログは残しつつ `docs/` 内の該当ドキュメントを更新すること
- 実装やテストをする際は、必ず `docs/` 内の最新版ドキュメントを参照すること
